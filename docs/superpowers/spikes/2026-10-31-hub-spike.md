Owner-run. Agents cannot read Claude credentials. Output goes to `spikes/cloud-sessions/out/` (git-ignored).

## Run commands

```text
dotnet run --project spikes/cloud-sessions -- q9 --answer-via tool-result
dotnet run --project spikes/cloud-sessions -- q9 --answer-via control-response
dotnet run --project spikes/cloud-sessions -- q9 --skills-probe
```

Expected: one of the first two makes the model reply with "Banana". Raw events land in `out/q9-events.jsonl` (pending item) and `out/q9-answered.jsonl` (after the answer). ## Results

### Answer route and shape (owner runs, 2026-10-31; 3 runs)

**How a question appears.**
1. The worker emits an assistant `tool_use` named `AskUserQuestion`.
2. It then emits a `control_request` event with `request.subtype: "can_use_tool"`, `tool_name: "AskUserQuestion"`, `requires_user_interaction: true`, `input.questions[]` (`question`, `header`, `multiSelect`, `options[{label, description}]`) and a `request_id`.
3. While the question waits, `GET /v1/sessions/{id}` shows `session_status: requires_action`, `post_turn_summary.status_category: need_input` and `needs_action: "Approve or deny AskUserQuestion"`.

**What a real answer looks like.** In every run, a client other than the spike answered within about 10–40 s. Its `initialize` request named `sdkMcpServers: ["ccd_session"]`, which is the Claude desktop app.
- The answer is a `control_response`:
  ```json
  {"type":"control_response","response":{"subtype":"success","request_id":"<can_use_tool request_id>",
   "response":{"behavior":"allow","toolUseID":"<tool_use id>","tool_name":"AskUserQuestion",
     "updatedInput":{"questions":[...original...],"answers":{"<question text>":"<option label>"}}}}}
  ```
- The worker then writes a `tool_result` user event: `Your questions have been answered: "Pick a fruit"="Banana"...`.
- **A question is pending** while its `can_use_tool` `request_id` has no `control_response` with the same `request_id`.

**Spike's own answer: inconclusive.**
- Both of the spike's posts (`tool-result` and `control-response`) returned HTTP 200, but they arrived after the question was already answered.
- The orphan `tool_result` confused the model ("The message from the other session came through empty").
- `q9` now sends the exact client shape (`toolUseID` and `tool_name` added). **To do:** rerun `q9 --answer-via control-response` with no Claude app or claude.ai tab open on the session.

**Fixtures:** `runtime/tests/Fyrd.Core.Tests/Fixtures/ask-user-pending.json` holds the events before the answer, and `ask-user-answered.json` holds all of them. Large `control_response` payloads are trimmed.
