Plan 2 Task 9: the first real end-to-end run of Fyrd on Claude Code cloud sessions. The owner ran it with their claude.ai login; the controller watched through the local Board API (`GET /api/board`) and GitHub.

- Fyrd started with `/fyrd:up` from `main`. The plugin was installed from this repo as a directory marketplace, so `CLAUDE_PLUGIN_ROOT` is the repo itself.
- Environment: `env_011v4b3WBhRMaGGti6Qw747c` (Anthropic-hosted).
- Spec: "test" on `servicetitan/titan-lens-ossie`. Add `docs/fyrd-smoke.md` with one sentence.
- Defaults: lead `claude-opus-5-5` in permission mode `auto`; peers `claude-sonnet-5-5`; squad cap 4.

## Run 1: failed (fixed in `8c62bbf`)

- The lead launched, emitted its units, created the integration branch, and created an implementer.
- The implementer session failed at startup: "An unexpected error occurred while setting up the repository".
- **Root cause:** the personas named the integration branch `fyrd/<specId>` and the unit branches `fyrd/<specId>/<unitId>`. Git can't hold a branch `X` and a branch `X/y` at the same time. Reproduced locally: `cannot lock ref 'refs/heads/fyrd/20261030-test/smoke-doc': 'refs/heads/fyrd/20261030-test' exists`. The cloud-session spike never hit this because its branch names were siblings.
- **Fix:** integration is now `fyrd/<specId>/integration` and units are `fyrd/<specId>/unit/<unitId>`. The lead persona now explicitly forbids a bare `fyrd/<specId>` branch, and `LeadPromptTests` enforces that.

## Issues found

1. **Spec IDs can be reused, and old sessions bleed in.** Run 2's spec was also titled "test" on the same day, so it got the same ID (`20261030-test`) as the deleted Run 1 spec. Because sessions are discovered by the tag `fyrd-spec-<specId>`, the Board also listed Run 1's archived implementer. **Plan 3:** add a short random suffix to spec IDs so a deleted spec's ID is never reused. Also consider ignoring archived peer sessions when deriving unit stage.
2. **Cleanup is manual.** Fyrd doesn't archive finished peers or the lead, and the auto-mode safety check blocks agents from deleting remote branches. The owner deleted the `fyrd/20261030-test/*` branches by hand. **Plan 4** (handoff) should decide what happens to branches and sessions after the PR.
